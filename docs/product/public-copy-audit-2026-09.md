# Rebase 公共官网固定文案审查与优化建议

审查日期：2026-09-08  
审查对象：公共官网（`apps/web`）及其公共默认配置、种子内容  
状态：已完成盘点，尚未直接修改线上文案

## 1. 审查范围与方法

本次审查覆盖：

- 页面：`/`、`/about`、`/geekdaily`、`/articles`、`/events`、`/who-is-hiring`、`/contributors` 及各详情页、404 页
- 全局：页头、导航、页脚、二维码弹窗、卡片、分区标题、空状态和错误状态
- 发现类输出：全站及各栏目 RSS 的标题和描述
- 默认内容：`apps/api/src/lib/site.ts` 与 `scripts/seed/baseline-data.mjs` 中会进入公共页面的默认文案

方法是沿着公共页面渲染路径阅读源码，逐项登记固定字符串、动态字段的兜底文案和种子内容，并对照 `apps/web/design_principles.md` 中的“内容优先、社区媒体高于营销、交互必须诚实”原则。

本次不审查管理后台界面文案，也不改写用户或招聘方提交的全部动态正文；动态内容部分只给出统一的编辑规则。

## 2. 结论摘要

### P0：发布前必须确认

1. **品牌定位语重复且来源分散。** “由中国开发者们在业余时间用热爱建立……”同时存在于站点默认配置、首页、About 和种子数据，修改容易漂移；“非营利、公益性”属于对外事实/法律属性，需由负责人确认最终表述。
2. **栏目和渠道命名不统一。** `Who-Is-Hiring`、`Who is hiring`、`招聘`，以及 `Twitter`、`X / Twitter` 并存；导航还出现“关于Rebase”“贡献者们”等格式不一致。
3. **存在可能误导或过时的承诺。** GeekDaily 文案写“每天更新”“最稳定”“最常用”，首页统计值和固定联系人也可能随时间变化；应改成可验证、可维护的描述。

### P1：应在下一轮文案更新中完成

1. 首页分区说明偏长，多个区块重复解释“社区是什么”，削弱内容发现路径。
2. 招聘和活动的免责声明、报名/投递状态说明不够直接；部分文字像内部运营术语。
3. 空状态、错误状态和 404 使用“没有被找到”等被动句式，缺少明确下一步。
4. RSS 元数据仍是英文，和中文网站主界面不一致。

### P2：集中润色时完成

1. 中英文混排、英文大小写和空格规则不稳定（`github`、`Github`、`Rebase极客日报`、`搜索与RSS` 等）。
2. 种子招聘、活动和贡献者资料中存在大量未经统一的英文职位、地点和行业术语。
3. 详情页的 `Longform Dispatch`、`链接规范` 等装饰或技术词对普通读者增益有限。

## 3. 统一词汇与格式基线

| 场景 | 建议统一写法 | 说明 |
| --- | --- | --- |
| 站点短名 | `Rebase` 或 `Rebase 社区` | 同一页面不要在两者之间来回切换 |
| 站点全称 | `Rebase Community` | 只在品牌介绍、SEO 或官方英文场景使用 |
| GeekDaily | 首次出现用 `GeekDaily（极客日报）`，后续用 `GeekDaily` | 中文读者先获得含义 |
| 招聘栏目 | 面向读者写 `招聘` 或 `招聘频道` | `Who-Is-Hiring` 保留为项目/仓库官方名或 URL 语境 |
| GitHub | `GitHub` | 禁止 `github`、`Github` |
| X | `X`；必要时写 `X（原 Twitter）` | 页面和页脚只选一种 |
| Bilibili | `B 站` | 保持现有中文习惯和空格 |
| RSS | `RSS` | 中文与英文缩写之间保留半角空格，如“订阅 RSS” |
| Issue | `GitHub Issue` | 首次出现说明为“GitHub Issue”即可，不使用 `issue` |
| 连接符 | 中文语句使用中文标点；元数据继续使用 `·` | 不在同一类信息中混用 `-`、`/`、`·` |
| 状态 | `即将举行`、`正在报名`、`往期活动`、`岗位已过期` | 状态词和行动按钮分开，避免一个词承担两种含义 |

如果某个项目有正式英文品牌（例如 `Web3Camp`、`Event Pool`），保留其官方拼写；中文解释放在描述中，不擅自改品牌名。

## 4. 分页面审查与改写方案

### 4.1 全局页头、导航与页脚

来源：`apps/api/src/lib/site.ts:352-358`、`apps/web/src/components/SiteHeader.astro`、`apps/web/src/components/SiteFooter.astro`、`scripts/seed/baseline-data.mjs:1-82`

| 编号 | 当前文案/现象 | 问题 | 建议文案或动作 | 优先级 |
| --- | --- | --- | --- | --- |
| G-01 | `Who-Is-Hiring`、`Who is hiring`、`招聘`并存 | 同一栏目有三套名字，读者难以判断是否同一入口 | 导航、页脚站点入口统一为 `招聘`；项目外链标题保留 `Who-Is-Hiring` | P0 |
| G-02 | `贡献者们` | “们”是口语化尾缀，和页面标题“贡献者”不一致 | 改为 `贡献者` | P1 |
| G-03 | `关于Rebase` | 中英文之间缺空格 | 改为 `关于 Rebase` | P1 |
| G-04 | 页脚 `About Rebase`、`Articles` 等英文，导航为中文 | 语言体系不一致 | 页脚站点入口改为 `关于 Rebase`、`文章`、`招聘`、`活动`、`贡献者` | P1 |
| G-05 | `Twitter` 与 `X / Twitter` 并存 | 渠道品牌已经变化，显示不一致 | 统一显示 `X`；如需兼容旧认知，在 About 首次写 `X（原 Twitter）` | P0 |
| G-06 | `Copyright © Rebase Community. All rights reserved.` | 中文页面出现完整英文法律句，语气和其他页脚不一致 | 法务确认后优先使用 `© Rebase Community`；如必须保留法律句，所有页面保持原文 | P2 |
| G-07 | 页脚摘要直接由 tagline 拼接 | tagline 改动会影响多个位置，且可能出现重复句号 | 建立一条“站点一句话介绍”作为唯一来源；渲染时只负责展示，不再拼接 | P0 |
| G-08 | 微信/QQ 二维码提示 | 基本清晰，但 QQ 提示重复“加入” | 微信：`打开微信，扫描二维码关注 Rebase 公众号。`；QQ：`打开 QQ，扫描二维码加入 Rebase QQ 群（群号：1001507060）。` | P2 |
| G-09 | 详情页无障碍标签 `Breadcrumb` | 屏幕阅读器会读出英文，和中文界面不一致 | 改为 `面包屑导航` | P2 |

导航推荐成稿：`首页｜极客日报｜招聘｜文章｜活动｜贡献者｜关于 Rebase`。

### 4.2 首页

来源：`apps/web/src/pages/index.astro:27-183`、`apps/api/src/lib/site.ts:38-48`

| 编号 | 当前文案 | 主要问题 | 建议改写 |
| --- | --- | --- | --- |
| H-01 | `建设面向开发者和创新者的社区` | “创新者”范围模糊，像口号 | `面向开发者的社区媒体` |
| H-02 | `这是一个由中国开发者用热爱和业余时间共同维护的非营利、公益性开发者社区。` | 与 hero/ About 重复；“用热爱”偏宣传；“中国”与法律属性需确认 | `Rebase 是一个由开发者共同维护的非营利社区，持续整理公开内容、机会与协作。`（法律属性确认后使用） |
| H-03 | `刚刚更新` | 没有日期时会制造“刚刚发生”的错觉 | `暂无发布日期`；如果业务保证实时性，再使用 `刚刚更新` |
| H-04 | GeekDaily 分区说明“最稳定”“紧随时代变化”“搜索与RSS最常用” | 主观比较、不可验证，且缺空格 | `持续更新技术内容与行业信号，支持按期浏览、搜索和 RSS 订阅。` |
| H-05 | 文章说明“从产品、社区、新技术、新探索到信息架构……” | 罗列过宽，读者不知道能看到什么 | `记录产品、社区、技术与实践中的真实想法。` |
| H-06 | 招聘说明“在社区github上提交”“最简单的格式筛选”“大家需要认真辨别” | 大小写错误；口语化且责任边界不清 | `岗位由招聘方提交，社区仅做基础格式整理，不对信息真实性或招聘结果负责，请在投递前自行核实。` |
| H-07 | 活动说明“主办和参与合作……在github上提交的活动” | “参与合作”语义不明，提交渠道没有说明 | `这里汇总 Rebase 主办、参与或社区提交的活动，可查看近期安排与历史记录。` |
| H-08 | `由更多真实的人，一起把社区持续往前推`、`先看见真实的人，再进入完整的贡献者档案。` | 两句都在做情绪表达，信息密度低且互相重复 | 分区标题：`认识贡献者`；说明：`志愿者、编辑和长期协作者共同维护 Rebase。` |
| H-09 | `内容整理、活动组织、推荐协作与长期共建，都会慢慢沉淀成可被看见的记录。` | “慢慢”“可被看见”抽象 | `内容、活动和协作记录会持续沉淀在公开档案中。` |
| H-10 | RSS 说明 `通过 RSS 持续追踪...` | “追踪”略带监控语气 | `订阅 RSS，持续接收 Rebase 的公开更新。` |

首页首屏推荐成稿：

- 眉题：`面向开发者的社区媒体`
- 标题：`Rebase 是一个持续更新的开发者社区。`
- 摘要：`我们把极客日报、文章、活动、招聘与协作项目整理成可阅读、可订阅、可回看的公共入口。`
- CTA：`浏览 GeekDaily`、`查看招聘`

### 4.3 About 页面

来源：`apps/web/src/pages/about.astro:9-41`、`apps/api/src/lib/site.ts:53-56`、`scripts/seed/baseline-data.mjs:84-110`

| 编号 | 当前文案/现象 | 问题 | 建议 |
| --- | --- | --- | --- |
| A-01 | 默认标题再次使用“由中国开发者们在业余时间用热爱建立……” | 与首页重复且过长，不像 About 页标题 | 标题：`关于 Rebase`；摘要：`了解 Rebase 的社区定位、栏目和参与方式。` |
| A-02 | 空状态：`关于页内容正在整理中。我们会很快补充...` | “很快”是无期限承诺；无下一步 | `关于页内容暂未发布。你可以先浏览社区栏目或贡献者介绍。` 并提供对应链接 |
| A-03 | 栏目名中混用 `Who is hiring`、`Event Pool`、中文名 | 读者无法判断哪些是项目官方名 | 采用“官方名 + 一句中文解释”；官方品牌拼写不翻译 |
| A-04 | 联系方式直接列出大量 URL 和地址 | 可读性弱，且部分渠道/地址可能失效 | 使用分组链接；捐赠地址增加网络、风险提示和“以多签确认页为准”说明（由运营/法务确认） |

About 页面不应承担首页全部定位语；它应补充“我们如何协作、如何参与、如何联系”，而不是再次解释站点存在的原因。

### 4.4 GeekDaily 列表、搜索与详情

来源：`apps/web/src/pages/geekdaily/index.astro:53-165,330-614`、`apps/web/src/pages/geekdaily/[slug].astro:10-155`

| 编号 | 当前文案/现象 | 问题 | 建议 |
| --- | --- | --- | --- |
| D-01 | SEO 标题 `Rebase极客日报` | 缺少中英文空格 | `Rebase 极客日报` |

| D-03 | 搜索 placeholder `搜索期数、标题、推荐语、条目标题或推荐人` | 信息完整但偏长 | `搜索期号、标题、推荐语或推荐人` |
| D-04 | `找到 X 期`、`共 X 期` | 期目概念没有在首次使用时说明 | 首次说明 `共 X 期 GeekDaily`；后续可简写为 `X 期` |
| D-05 | `没有找到匹配的 GeekDaily` | 语气不完整，缺少调整建议 | `未找到匹配的 GeekDaily 期目`；辅助文案：`换个关键词，或清空筛选条件后重试。` |
| D-06 | `正在加载历史检索数据...`、`检索暂不可用` | “检索”偏技术化，和搜索入口不一致 | `正在加载搜索索引...`、`搜索暂不可用` |
| D-07 | `归档暂不可用`、`归档数据加载失败。` | 两处表达重复，且没有动作 | `归档加载失败，请稍后刷新；你也可以先浏览已显示的内容。` |
| D-08 | 详情侧栏 `链接规范` | 面向读者暴露实现术语 | `固定链接` |
| D-09 | 详情侧栏说明“固定路径，适合从搜索结果重新进入” | 解释实现而非读者收益 | `详情页保留逐条推荐和固定链接，方便从搜索或订阅再次访问。` |
| D-10 | 固定结尾“持续整理值得关注的技术内容与行业信号” | 可保留，但与列表 hero 的“信号”叙述重复 | 详情页保留一句即可，列表页改为直接说明搜索、筛选和订阅能力 |

推荐列表 hero：`GeekDaily 持续整理值得关注的技术内容与行业信号，支持按期浏览、搜索和 RSS 订阅。`

| J-09 | `投递方式`、`继续关注`、`更多岗位` | 前两项动作不完全对应 | 保留 `投递方式`、`更多岗位`；`继续关注`改为 `继续浏览` |
| J-10 | 招聘卡片直接展示薪资，但没有货币/周期规范 | 动态数据容易被误读 | 运营录入规范要求明确币种、税前/税后（如适用）和周期；不是靠前端猜测 |

招聘页不应暗示 Rebase 对岗位真实性背书；免责声明应在列表 hero 和详情投递区各出现一次即可，避免重复堆叠。

### 4.9 404、空状态和错误状态

来源：`apps/web/src/pages/404.astro`、各详情页 404 分支、`apps/web/src/pages/geekdaily/index.astro:330-614`、列表空状态组件

现有页面大量使用“暂时没有被找到”这一被动句式，例如“这页内容暂时没有被找到”“这个招聘页面暂时没有被找到”。建议全站采用同一模板：

- 页面标题：`找不到这个页面`
- 详情标题：`暂时找不到这篇文章` / `暂时找不到这个活动` / `暂时找不到这个岗位` / `暂时找不到这期 GeekDaily`
- 说明：`链接可能已失效，或内容已经移动。你可以返回列表继续浏览。`
- 主按钮：按内容类型使用 `回到首页` 或 `返回列表`

“更多文章正在整理中”“历史活动档案会继续补全”等空状态可以保留“持续更新”的积极语气，但不要使用无法兑现的时间词（如“很快”）；空状态必须同时提供可执行的返回或订阅动作。

### 4.10 RSS 与其他发现类输出

来源：`apps/web/src/pages/rss.xml.ts`、`apps/web/src/pages/geekdaily/rss.xml.ts`、`apps/web/src/pages/articles/rss.xml.ts`、`apps/web/src/pages/events/rss.xml.ts`、`apps/web/src/pages/who-is-hiring/rss.xml.ts`

当前 feed 的标题和描述为英文：`Rebase feed`、`GeekDaily feed`、`Rebase articles`、`Rebase events`、`Rebase hiring`。建议改为中文，与页面导航一致：

| Feed | 标题 | 描述 |
| --- | --- | --- |
| 全站 | `Rebase 社区 RSS` | `Rebase 社区最新的公开更新。` |
| GeekDaily | `Rebase 极客日报 RSS` | `Rebase 极客日报的最新期目。` |
| 文章 | `Rebase 文章 RSS` | `Rebase 社区最新文章。` |
| 活动 | `Rebase 活动 RSS` | `Rebase 社区最新活动更新。` |
| 招聘 | `Rebase 招聘 RSS` | `Rebase 社区最新招聘信息。` |

RSS item 的正文继续使用内容自身的标题和摘要；不要把“最新”“最稳定”等营销形容词写入 feed 描述。若 API 域名的旧 RSS 路由仍对外可发现（`apps/api/src/routes/root.ts`），应同步改名，或明确它是兼容入口并与官网 feed 保持同一套词表。

## 5. 默认配置与种子内容的专项问题

### 5.1 文案来源重复

同一套站点定位、首页 hero 和 About 标题同时写在：

- `apps/api/src/lib/site.ts` 的 `defaultSiteSettings`、`defaultHomePage`、`defaultAboutPage`
- `scripts/seed/baseline-data.mjs` 的 `siteSettings`、`aboutPage`
- `apps/web/src/pages/index.astro` 的固定补充文案

建议下一次代码改动只保留一个规范来源；如果当前架构暂时必须保留两份，至少在文件顶部注明“修改后必须同步另一处”，并在发布检查中增加一次全文搜索。不要只改首页而忘记 API 默认值或本地 bootstrap 数据。

### 5.2 种子招聘内容

`baseline-data.mjs` 中的岗位正文整体可读，但中英文术语、职位名和地点格式混杂，例如：

- `devrel program manager`、`technical writer` 等职位全为英文小写
- `remote / shanghai friendly`、`remote / china time zone preferred` 等地点表达不统一
- `protocol narrative`、`pipeline`、`memo`、`portfolio`、`thread`、`review`、`roadmap`、`BD` 混在中文句子中
- `$4,000 - $6,500 / month` 没有统一短横线、币种和周期格式

建议采用以下录入规则，而不是由前端对动态内容做危险的自动翻译：

1. 职位保留招聘方官方英文名；另设中文职位名时，统一使用“中文名（English title）”。
2. 地点使用 `远程｜上海优先`、`线上`、`深圳` 等可扫描格式；不要使用全小写英文句子。
3. 薪资必须填写币种和周期，例如 `USD 4,000–6,500/月`；是否展示税前/税后由招聘方明确。
4. 常见行业词建立词表：`builder`、`maintainer`、`editor` 等首次出现附中文解释，后续保持一种写法。

### 5.3 种子活动与贡献者内容

活动标题大量使用英文城市/活动名（`Rebase Guangzhou Maintainer Breakfast`、`Community Media Retrospective`），正文又混用 `builder`、`operator`、`archive nerd` 等标签；贡献者 headline 几乎全部为英文。

如果这些是面向中文读者的示例内容，建议改为“中文标题 + 官方英文名（可选）”，并把“适合谁来”的标签转换为中文短语；如果它们只是测试数据，则应明确标记为测试数据，避免被误当作正式公共内容。

### 5.4 种子文章内容

种子文章的标题和摘要以中文为主，但存在 `7 min read`、`5 min read`、`6 min read` 等英文阅读时长，以及 `Signal over noise`、`signal desk`、`issue`、`URL` 等中英文混排。建议：

- 阅读时长在中文卡片中显示为 `约 7 分钟阅读`；若保留原始英文值，应在录入或渲染层完成一次明确的本地化映射。
- `signal over noise` 等英文小标题可以作为文章本身的风格，不要把它们当成全站 UI 词；摘要、卡片元数据和 SEO 仍使用中文。
- 文章标签（`community`、`product`、`media` 等）需明确是内部检索标签还是面向读者的显示标签；如果面向读者，建立中文显示名，不直接把数据库 slug 当成文案。

## 6. 建议的落地顺序

### 第一批：统一事实和命名（P0）

- 确认“非营利/公益”及“中国开发者”是否仍是官方定位
- 确认 `Rebase`、`Rebase 社区`、`Rebase Community` 的使用边界
- 统一导航、页脚、SEO、RSS 的栏目名和渠道名
- 删除或改写“每天更新、最稳定、最常用”等无法持续证明的表述
- 清理 `default*` 与 seed 的重复文案来源

### 第二批：改写读者路径（P1）

- 首页各分区缩短为“内容是什么 + 用户能做什么”
- 重写招聘真实性提示、活动报名状态和详情页行动按钮
- 统一 404、空状态、错误状态模板，并为每个状态提供下一步链接
- About 页补充参与方式，不再使用“很快补充”

### 第三批：编辑规范和润色（P2）

- 建立中英文品牌、空格、大小写和连接符词表
- 统一种子/生产内容的职位、地点、薪资和行业术语格式
- 将 `Longform Dispatch`、`链接规范` 等低价值技术/装饰文案改为中文或移除
- RSS 和 API 兼容 feed 使用同一份标题/描述词表

## 7. 验收清单

文案改动合并前，逐项检查：

- [ ] 全站导航、页脚、按钮和 SEO 标题使用同一栏目名称
- [ ] 搜索 `Who-Is-Hiring`、`Who is hiring`、`Github`、`github`、`关于Rebase`、`Rebase极客日报` 后，只剩官方项目名或 URL 必要场景
- [ ] 首页、About、页脚不重复堆叠同一段品牌定位语
- [ ] GeekDaily 没有未经确认的“每天更新/最稳定/最常用”等事实承诺
- [ ] 招聘页明确“社区仅做基础整理，不为岗位真实性背书”
- [ ] 活动页能区分报名、详情、回顾和历史链接
- [ ] 所有 404、空状态、错误状态都给出下一步动作
- [ ] RSS 标题和描述与中文主站一致
- [ ] 默认配置与 seed 的同名文案已同步
- [ ] 桌面端和移动端实际浏览，确认改写后没有截断或换行歧义

以上建议先作为文案基线；真正改代码或后台内容前，应由社区负责人确认品牌定位、渠道名称、捐赠说明和招聘免责声明的最终版本。
